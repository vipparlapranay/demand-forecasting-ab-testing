# Demand Forecasting and A/B Testing

An end-to-end weekly multi-series demand forecasting and randomized experiment analysis project. All checked-in benchmark results come from deterministic **synthetic data**; they are not company sales, causal business impact, or production performance claims.

## What is included

- Reproducible synthetic weekly demand for **12 products × 8 stores = 96 series**, with four years of generated history.
- LightGBM with lag (1/2/4/8/13/26/52), shifted rolling mean/standard deviation (4/13/26/52), store/product identity, promotional, and calendar features.
- **Five rolling-origin folds**, each forecasting four weeks recursively, compared with a 52-week seasonal-naive forecast.
- WAPE (weighted absolute percentage error) aggregated over all product/store holdout observations.
- Conversion experiment power/sample-size calculation and a two-sided two-proportion z-test using a deterministic, randomly assigned synthetic user sample.
- CSV predictions, experiment records, and `metrics.json` generated by the runnable CLI and uploaded as a GitHub Actions artifact.

## Run locally

Python 3.10+:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m demand_forecasting --output-dir output
python -m pytest -q
```

Provide your own aggregated weekly data with columns `week_start`, `product_id`, `store_id`, and `demand`:

```powershell
python -m demand_forecasting --input-csv data\weekly_demand.csv --output-dir output
```

Rows must be unique for each week/product/store; demand must be non-negative. For a useful 52-week seasonal baseline, supply at least 156 weeks (the default rolling-origin setup requires 156). Future planned promotion flags are not assumed known in the evaluation; synthetic test weeks therefore use `promo_flag=0`.

## Experimental design

The default experiment is randomized at the **user** level, with 10,000 synthetic users per arm. The primary metric is binary conversion. Before looking at the simulated result, the analysis calculates the per-arm sample size for 80% power, two-sided alpha 0.05, a 12% baseline rate, and a 1.5 percentage-point minimum detectable effect. The simulated assignment is tested with a two-sided two-proportion z-test, reporting conversion counts, rates, absolute/relative lift, a 95% approximate confidence interval, p-value, and significance conclusion.

Do not treat synthetic conversion data as evidence about a real intervention. For an actual experiment, pre-register the primary metric, randomization unit, MDE, duration, exclusion rules, guardrails, and analysis before observing outcomes; check assignment quality and sample-ratio mismatch.

## Metrics

`output/metrics.json` records the measured row counts, number of series/folds/holdout weeks, LightGBM and seasonal-naive WAPE, whether the model beats baseline, power/sample size, and A/B test result. Metrics are produced by executing the pipeline, not hard-coded into the report. CI uploads this JSON as an artifact.

The committed [`results/metrics.json`](results/metrics.json) was generated by running the default benchmark. On this deterministic synthetic dataset, five rolling-origin folds scored 1,920 product-store/week predictions across 20 holdout weeks. LightGBM WAPE was **14.3276%**, versus **18.0712%** for seasonal naive, a **20.7158% relative WAPE reduction**.

The simulated A/B test used 10,000 users per arm. Sample-size planning estimated **7,756 users per arm** for 80% power to detect a 1.5 percentage-point lift from a 12% baseline at two-sided alpha 0.05. The seeded fixture observed 12.35% control conversion and 11.88% treatment conversion (−0.47 percentage points); **p = 0.308437**, with a 95% confidence interval for the lift of **[−1.3744, 0.4344] percentage points**. This synthetic result is **not statistically significant** and is not evidence about a real treatment.
